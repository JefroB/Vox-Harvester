# Local Model Review Checklist

## Purpose

When reviewing code generated by the local Ollama models, focus on their known blind spots. These models produce structurally sound code but consistently miss certain categories of bugs.

## Known Weaknesses (Both Models)

### Concurrency & Thread Safety
- **Sleeping inside locks** — The #1 recurring bug. Models put `time.sleep()` inside `with self._lock:` blocks, causing deadlocks under load.
- **Lock scope too broad** — Holding locks across I/O or long operations.
- **Race conditions** — Missing locks around compound check-then-act operations.
- **Fix pattern:** Lock only around state reads/writes. Release before sleeping. Use condition variables for waiting.

### Cleanup & Resource Management
- **Stub cleanup** — Models write a `_cleanup()` method that doesn't actually remove anything.
- **No daemon threads** — Background cleanup timers that prevent process exit.
- **Missing shutdown** — No way to stop background threads cleanly.
- **Fix pattern:** Use `threading.Timer` with `.daemon = True`. Provide a `shutdown()` method.

### Edge Cases
- **Division by zero** — Rate=0 not validated.
- **Empty input** — Missing handling for None, empty strings, zero values.
- **Overflow** — Requesting more tokens than burst capacity.
- **Fix pattern:** Validate at function entry. Raise `ValueError` with descriptive messages.

## Model-Specific Notes

### qwen2.5-coder:7b (Fast)
- Gets the shape right but misses edge cases
- Often produces a single class that mixes concerns
- Minimal input validation
- **Good for:** Boilerplate, simple functions, data structures
- **Review focus:** Correctness, separation of concerns, missing validation

### qwen3-coder:30b-a3b (Heavy)
- Better structure (uses dataclasses, proper separation)
- Good documentation and type hints
- Still has concurrency bugs
- Cleanup is often a stub
- **Good for:** Complex structures, APIs, multi-class designs
- **Review focus:** Thread safety, actual cleanup implementation, blocking behavior

## Review Checklist (Quick Scan)

1. ☐ Any `time.sleep()` inside a `with lock:` block? → DEADLOCK
2. ☐ Any infinite loop inside a lock? → DEADLOCK
3. ☐ Input validation present for public methods?
4. ☐ All stated requirements actually implemented (not stubbed)?
5. ☐ Resources cleaned up (timers cancelled, threads joined)?
6. ☐ Error messages include context (not just "Error occurred")?
7. ☐ Imports all present and used?
8. ☐ Return types match docstring claims?
