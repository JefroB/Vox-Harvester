
TOKEN SAVINGS METHODOLOGIES FOR SUBAGENT SYSTEM

Existing Techniques
-------------------
1. Hierarchical agents (local model handles most work, larger model only for escalation)
2. Selective code retrieval (grep/ripgrep/tree-sitter extraction instead of full-file loading)

Additional Techniques
=====================

1. Semantic Code Summaries
--------------------------
Generate and cache summaries for files, modules, and components.

Example:
- File name
- Exported symbols
- Purpose
- Dependencies
- Key responsibilities

Workflow:
1. Read summaries first.
2. Read source only when necessary.

Benefits:
- Reduces repeated file reads.
- Often cuts 70-90% of source retrieval.

2. Symbol-Level Retrieval
-------------------------
Retrieve only:
- Classes
- Functions
- Methods
- Structs
- Enums

Instead of loading an entire file, load only the symbol being modified.

Recommended:
- Tree-sitter
- AST indexing

Benefits:
- Dramatic reduction in retrieved code volume.

3. Dependency Radius Limiting
-----------------------------
Build a dependency graph.

Example:
Target:
- ArrangementCoach.cpp

Direct dependencies:
- GenreEngine.cpp
- SuggestionEngine.cpp

Exclude unrelated modules unless escalation occurs.

Benefits:
- Prevents unnecessary context expansion.

4. Conversation Compression
---------------------------
Periodically summarize active conversations.

Store:
- Current goal
- Completed work
- Open tasks
- Architectural decisions

Replace long discussions with compact state snapshots.

Benefits:
- Reduces long-session token growth.

5. Decision Log Memory
----------------------
Maintain a persistent decisions file.

Example:
.decisions.md

Contents:
- Architectural decisions
- Technology choices
- Constraints
- Rejected approaches

Benefits:
- Prevents agents from re-analyzing solved problems.

6. Intent Routing
-----------------
Classify tasks before selecting a model.

Examples:

Small Model:
- Formatting
- Renaming
- Comment updates

Medium Model:
- Refactoring
- Unit tests

Large Model:
- Architecture
- System redesign

Benefits:
- Matches token spend to task complexity.

7. Change-Set Context
---------------------
Load diffs instead of full files.

Provide:
- Changed region
- Surrounding function
- Relevant dependencies

Benefits:
- Minimizes code supplied to the model.

8. Architectural Maps
---------------------
Generate project maps.

Store:
- Modules
- Responsibilities
- Public APIs
- Dependencies

Agent navigation process:
1. Read architecture map.
2. Locate module.
3. Load code only if needed.

Benefits:
- Faster context acquisition.

9. Two-Pass Planning
--------------------
Pass 1:
- Identify required files and symbols.

Pass 2:
- Retrieve only those items.

Benefits:
- Eliminates exploratory retrieval.

10. AST Delta Storage
---------------------
Store hashes for symbols.

Example:
AudioEngine::ProcessBuffer -> Hash

If unchanged:
- Reuse cached understanding.

Benefits:
- Avoids reloading stable code.

11. Multi-Level Context Windows
-------------------------------
Level 0:
- Project summary

Level 1:
- Module summaries

Level 2:
- Actual source code

Load deeper levels only when necessary.

Benefits:
- Most tasks never require full source loading.

12. Embeddings + Symbol Search
------------------------------
Use semantic retrieval.

Example Query:
"Find code responsible for genre transition weighting"

Retrieve:
GenreWeightEngine::CalculateTransitionScore()

Benefits:
- Direct access to relevant symbols.
- Reduces search noise.

13. Proof-Before-Read Strategy
------------------------------
Before opening a file, require the agent to answer:

- Why is this file needed?
- Which symbol is being sought?
- What decision depends on this information?

If justification is weak:
- Do not load the file.

Benefits:
- Reduces unnecessary retrieval.

14. Specialized Micro-Agents
----------------------------
Separate responsibilities:

- Architecture Agent
- Retrieval Agent
- Refactor Agent
- Testing Agent
- Documentation Agent

Each receives only the context required.

Benefits:
- Smaller context windows.
- Better specialization.

15. Context Snapshots
---------------------
Periodically save:

- Architecture state
- Current goals
- Completed tasks
- Open issues

Load snapshots before loading source code.

Benefits:
- Reduces repeated project onboarding.

Highest-Impact Recommendations
==============================

1. Symbol-level retrieval (Tree-sitter)
2. Cached code summaries
3. Decision logs
4. Two-pass planning
5. AST hash caching

Combined with selective file retrieval, these techniques can often reduce context consumption by an additional 50-80%.
